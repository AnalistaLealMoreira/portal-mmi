Portal MMI

Guia resumido para publicação e operação do portal Django em nuvem com SQL Server.

1. Arquitetura e requisitos

AplicaçãoPython 3.11+, Django 5.2.x, WSGI/ASGI e servidor Windows/Linux conforme a infraestrutura.
BancoSQL Server, backend mssql-django, pyodbc e ODBC Driver 17 ou superior.
Static filesExecutar collectstatic e servir STATIC_ROOT pelo proxy ou storage.
RedeHTTPS, DNS, proxy reverso e encaminhamento confiável do IP real do cliente.

2. Banco SQL Server

ItemValor
Servidorautomate.leal.local
Databaseportalmmi
Porta1433
DriverODBC Driver 17 for SQL Server
LoginLogin SQL fornecido pelo DBA; não registrar senha neste documento.
A aplicação precisa de db_datareader e db_datawriter. Migrações e DDL devem ser executados por DBA/conta administrativa.

3. Variáveis de ambiente

Criar um arquivo .env no diretório do projeto. Usar cofre de segredos em produção.

SECRET_KEY=gerar-um-segredo-longo-e-aleatorio
DEBUG=False
ALLOWED_HOSTS=portal.exemplo.com

DATABASE_BACKEND=mssql
DATABASE_NAME=portalmmi
DATABASE_USER=login-da-aplicacao
DATABASE_PASSWORD=senha-do-cofre
DATABASE_HOST=automate.leal.local
DATABASE_PORT=1433
DATABASE_DRIVER=ODBC Driver 17 for SQL Server
DATABASE_EXTRA_PARAMS=TrustServerCertificate=yes;
CONN_MAX_AGE=60

4. Instalação e publicação

python -m venv venv
# Windows PowerShell
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py check --deploy
python manage.py migrate
python manage.py migrate --plan
python manage.py collectstatic --noinput

Executar a aplicação com um servidor WSGI/ASGI gerenciado por serviço, supervisor ou plataforma cloud. Não usar runserver em produção.

5. Segurança e proxy

  • Forçar HTTPS e habilitar cookies seguros.
  • Configurar SECURE_SSL_REDIRECT, HSTS e CSRF_COOKIE_SECURE depois de validar o proxy.
  • O proxy deve remover cabeçalhos de IP recebidos do cliente e inserir o IP real de forma confiável.
  • Não expor diretamente a porta do processo Django.
  • Guardar SECRET_KEY e senha do SQL Server fora do Git.
  • Definir backup, retenção e teste de restauração do SQL Server.

6. Funcionalidades operacionais

PerfisAdministrador, Admin da Empresa, Diretor, Usuário Especial e Usuário Normal.
AuditoriaUsuário, link, IP, navegador e data/hora em AcessoLog.
RelatóriosLinks exibidos em iframe com escopo por empresa/setor/compartilhamento.
Marca d'águaCamada visual para Normal/Especial; não exibida para Diretor/Admin da Empresa.

7. Checklist de aceite

  • DNS e certificado HTTPS configurados.
  • O servidor alcança automate.leal.local:1433.
  • O ODBC Driver está instalado.
  • Variáveis do ambiente foram cadastradas no cofre.
  • manage.py check --deploy revisado.
  • migrate --plan sem pendências.
  • Login e CRUD testados.
  • Usuários Normal/Especial, Diretor e Admin da Empresa testados.
  • Auditoria e acesso aos relatórios validados.
  • Backup e restauração testados.
