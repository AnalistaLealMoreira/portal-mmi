Manual de configuração da máquina local

Versão de 01/10/2026 · Laravel 13 / PHP 8.4 · Repositório AnalistaLealMoreira/portal-mmi

1.Visão geral

Este manual prepara um computador Windows para rodar o Portal MMI em modo de desenvolvimento. No fim, o portal estará em http://localhost:8000, usando um banco SQLite local, sem tocar no banco de produção.

  • Tempo estimado: 20 a 30 minutos.
  • Lista de requisitos: o arquivo requirements.txt, nesta mesma pasta, resume tudo o que a máquina precisa ter.
  • Bibliotecas PHP: não se instalam uma a uma. O composer install lê o composer.json/composer.lock e baixa tudo para a pasta vendor/ (é o equivalente ao pip install -r requirements.txt do Django).
  • Front-end: Bootstrap, ícones, Chart.js e a fonte vêm de CDN. Não é preciso Node.js nem build de front-end.

Não aponte a máquina de desenvolvimento para o banco de produção. Use o SQLite local (padrão do .env.example). Conectar no SQL Server só com um banco de homologação e com autorização (seção 8).

3.Instalar e configurar o PHP

  1. Baixe o PHP 8.4 x64 (arquivo Zip, NTS ou TS) em windows.php.net/download e extraia para C:\php.

    Se o Windows reclamar de VCRUNTIME140.dll, instale o Visual C++ Redistributable x64.

  2. Adicione C:\php ao PATH do usuário (PowerShell, depois feche e abra o terminal): 
    [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";C:\php", "User")
  3. Crie o php.ini a partir do modelo de desenvolvimento: 
    Copy-Item C:\php\php.ini-development C:\php\php.ini
  4. Abra C:\php\php.ini e ajuste as linhas abaixo (tire o ; do começo): 
    extension_dir = "ext"

extension=curl
extension=fileinfo
extension=intl
extension=mbstring
extension=openssl
extension=pdo_sqlite
extension=sqlite3
extension=zip

memory_limit = 512M
date.timezone = America/Sao_Paulo
  5. Confira a versão e as extensões: 
    php -v
php -m | Select-String "curl|fileinfo|intl|mbstring|openssl|pdo_sqlite|sqlite3|zip"

    As oito extensões precisam aparecer na lista.

4.Composer e Git

  1. Instale o Composer com o instalador Composer-Setup.exe. Quando ele pedir o PHP, aponte para C:\php\php.exe.
  2. Instale o Git em git-scm.com (opções padrão).
  3. Configure seu nome e e-mail no Git (uma vez por máquina): 
    git config --global user.name "Seu Nome"
git config --global user.email "seu.email@empresa.com"
  4. Confira: 
    composer -V
git --version

O repositório é privado: peça acesso a AnalistaLealMoreira/portal-mmi antes de clonar. No primeiro git clone, o Git abre o navegador para você entrar na conta do GitHub.

5.Baixar e configurar o projeto

  1. Clone o repositório numa pasta de trabalho (exemplo: D:\): 
    cd D:\
git clone https://github.com/AnalistaLealMoreira/portal-mmi.git PortalMMI_L
cd PortalMMI_L
  2. Instale as bibliotecas PHP (cria a pasta vendor/): 
    composer install
  3. Crie o arquivo de configuração local e gere a chave da aplicação: 
    Copy-Item .env.example .env
php artisan key:generate

O .env.example já vem pronto para desenvolvimento. Os valores que importam:

VariávelValor localObservação
APP_ENV / APP_DEBUGlocal / trueMostra os erros detalhados na tela
APP_URLhttp://localhost:8000Endereço do php artisan serve
DB_CONNECTIONsqliteUsa database/database.sqlite
HASH_DRIVERdjangoSenhas no formato pbkdf2_sha256, compatíveis com o portal Django
PORTAL_FORCE_HTTPSfalseEm produção é true; localmente não há HTTPS
SESSION_DRIVER / CACHE_STOREfileFicam em storage/, sem tabelas extras

O .env não vai para o Git (está no .gitignore). Nunca coloque senhas reais em .env.example, no código ou em commits.

6.Banco de dados local

O arquivo do SQLite não vem no repositório (/database/*.sqlite está no .gitignore). Há duas opções:

Opção A: banco novo, vazio (recomendado)

  1. Crie o arquivo vazio e as tabelas do portal: 
    New-Item -ItemType File database\database.sqlite
php artisan migrate

    A migração cria as mesmas tabelas do Django (accounts_usuario, empresas_empresa, setores_setor, bi_links_linkbi etc.).

  2. Crie o primeiro administrador (o comando pede a senha duas vezes): 
    php artisan portal:criar-admin admin --email=admin@empresa.com
  3. Entre no portal com esse usuário e cadastre empresas, setores, links de BI e usuários pelas próprias telas.

Opção B: cópia de um banco existente

Se alguém da equipe passar um database.sqlite já preenchido (ou o db.sqlite3 do portal Django), copie para database\database.sqlite e rode php artisan migrate: ele só cria o que faltar e não altera os dados. Os usuários entram com as mesmas senhas.

Uma cópia com dados reais contém e-mails e acessos de pessoas (LGPD). Não envie esse arquivo por canais abertos e apague quando não precisar mais.

7.Rodar e acessar

php artisan serve

Abra http://localhost:8000 e entre com o administrador criado. O login aceita nome de usuário ou e-mail. Para parar o servidor, use Ctrl+C no terminal.

Para usar outra porta (por exemplo, se a 8000 estiver ocupada):

php artisan serve --port=8001

Confirmar que está tudo certo

Usuários com papel Usuário Normal só entram de redes cadastradas em Redes permitidas. Para testar esse papel localmente, cadastre 127.0.0.1/32 e ::1/128 como redes ativas.

8.Opcional: conectar no SQL Server

Só faça isto com um banco de homologação e com autorização do DBA. Para o dia a dia, o SQLite basta.

  1. Instale o ODBC Driver 18 for SQL Server (x64).
  2. Baixe os drivers PHP para SQL Server (5.13 ou superior). Copie para C:\php\ext as DLLs da sua versão do PHP, por exemplo php_pdo_sqlsrv_84_nts_x64.dll e php_sqlsrv_84_nts_x64.dll (use ts se o seu PHP for Thread Safe; php -v mostra qual é).
  3. Habilite no php.ini com o nome exato dos arquivos: 
    extension=php_pdo_sqlsrv_84_nts_x64.dll
extension=php_sqlsrv_84_nts_x64.dll
  4. Teste a rede e confira as extensões: 
    Test-NetConnection automate.leal.local -Port 1433
php -m | Select-String "sqlsrv"
  5. No .env, troque o bloco do banco (peça as credenciais ao DBA): 
    DB_CONNECTION=sqlsrv
DB_HOST=servidor-de-homologacao
DB_PORT=1433
DB_DATABASE=portalmmi_homolog
DB_USERNAME=usuario
DB_PASSWORD=senha
DB_TRUST_SERVER_CERTIFICATE=true
  6. Limpe o cache de configuração e confira: php artisan config:clear e php artisan about.

Fluxo sugerido para alterações: crie uma branch (git switch -c minha-alteracao), rode php artisan test antes do commit e abra um Pull Request para a main.

Ao mudar public/static/css/refino.css ou public/static/js/shell.js, aumente o ?v= correspondente em resources/views/layouts/app.blade.php para o navegador não usar a versão em cache. Os demais detalhes de arquitetura estão no README.md.

10.Problemas comuns

SintomaCausa provável e solução
php não é reconhecido como comandoC:\php não está no PATH, ou o terminal foi aberto antes da mudança. Feche e abra o terminal (seção 3, passo 2).
composer install reclama de extensão faltando (ext-intl, ext-fileinfo…)Extensão desabilitada no php.ini. Confira o extension_dir = "ext" e as linhas extension= (seção 3, passo 4). php --ini mostra qual php.ini está em uso.
Erro de SSL ao baixar pacotesextension=openssl desabilitada, ou proxy da rede. Habilite a extensão e, se houver proxy, configure HTTPS_PROXY.
No application encryption key has been specifiedFaltou php artisan key:generate.
Database file at path … database.sqlite does not existCrie o arquivo (seção 6, opção A).
could not find driverFalta pdo_sqlite (ou pdo_sqlsrv, se estiver usando SQL Server) no php.ini.
Página sem estilo, sem ícones ou sem gráficosO navegador não alcança cdn.jsdelivr.net/fonts.googleapis.com. Verifique internet, proxy ou bloqueio do firewall.
Login de Usuário Normal recusado por redeCadastre 127.0.0.1/32 e ::1/128 em Redes permitidas (seção 7).
Mudança no .env não surte efeitoConfiguração em cache. Rode php artisan optimize:clear.
Failed to listen on 127.0.0.1:8000Porta ocupada. Use php artisan serve --port=8001.
